## 3. Development strategy

**Base rule (roadmap)**: a phase only starts when the previous one is green
(build + test + clippy `-D warnings` + fmt). Do not skip phases.

**Per-ticket cycle**:

```
GitHub issue (template) → board Status=Todo
  → dedicated worktree (~/.vibe/worktrees/cpm-store/<task>) + short branch from origin/main
  → plan in the issue body → Status=Plan Review (gate 1, human for non-trivial choices)
  → implementation + tests (unit + wiremock + golden from PDF)
  → PR (template, Closes #N) → standalone CI green → Status=Code Review
  → rebase on main + merge → Status=Done
```

- **Git**: rebase rather than merge; combined PRs by retarget; conventional
  commits in English; no long-lived branches; **no writes into the main
  checkout** (worktree-guard): each task = one worktree.
- **Tests**: unit tests per module; `wiremock` integration at the transport
  level (`/nms/v1/...`); golden fixtures **generated at test time from the local
  PDFs** (`pdftotext`), never embedded (D9). Python: ruff + mypy strict +
  bandit + pytest (dockyard python domain enabled).
- **Conformance**: any PR that checks an SCR in `docs/conformance.md` updates the
  checklist in the same PR, with the name of the covering test.
- **Specs**: quote the spec section number in code comments and commits for any
  normative procedure; never invent a section.
- **Quality**: zero clippy warnings, MSRV 1.85 (lock committed, `--locked` check),
  `unsafe` forbidden outside `cpm-ffi`, `Result<T, CpmError>` at adapter boundaries.
- **Standalone CI** (S9): local `.github/workflows/ci.yml`, jobs build/test/lint/
  msrv/security/gitleaks (rust) + lint/typecheck/sast/test-python + mdformat.

## 4. Agent workflow (owner agents)

**One owner per domain**, a single active agent on a crate at a time. The orchestrator
(spawn with an explicit `config_name` — `plan-exec` to execute, `explore-flash`
to read) splits the work, assigns owners with a written mandate, and integrates.
Each owner reads `AGENTS.md`, `docs/architecture.md`, `docs/specs.md` and this file
**before** touching the code.

| Owner             | Scope                            | Mandate                                                                                              | Gate it is responsible for                                |
| ----------------- | -------------------------------- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| `spec-guardian`   | Normative conformance            | Exact section citations, `docs/conformance.md`, golden fixtures from the PDF                         | Every checked SCR has its named test                      |
| `ports-architect` | `cpm-core` (model + ports), ADRs | `StoreBackend`/`MessageStorage`/`SyncStateStore` ports, layering, `forbid(unsafe)`, `SyncState` (D3) | No port change without an ADR + human review              |
| `nms-owner`       | `cpm-nms` (REST adapter)         | Centralized `http.rs`, auth §5.2.1, folders §7.3.2, objects §7.3.3, sync §5.5, wiremock tests        | Wiremock tests green per endpoint                         |
| `msg-owner`       | `cpm-msg` (CPIM/MIME)            | Parse/serialize `message/CPIM` (RFC 3862) + MIME multipart, conversation mapping                     | Green round-trip on the annexes                           |
| `sync-owner`      | `cpm-client` (orchestration)     | First-time + steady-state strict sync §6.3.3, fallback §6.3.3.2 NOTE, stateless (D3)                 | 2 mocked clients converge                                 |
| `ffi-owner`       | `cpm-ffi` (C adapter)            | FFI contract (D5): tokio `OnceLock` runtime, C vtable, `catch_unwind`, cbindgen                      | `unsafe` confined to this crate, no panic crosses the ABI |
| `quality-gate`    | Cross-cutting quality            | zero-warning clippy, fmt, MSRV, cargo-deny, gitleaks, ruff/mypy/bandit, hooks                        | CI gate green before merge                                |
| `docs-owner`      | `docs/`, README, FILEMAP         | Docs consistency, roadmap/conformance up to date                                                     | Docs updated in the same PR                               |

**Common rules**: an owner never touches another owner's crate in the same
session; any divergence from an ADR goes through a new ADR; if a point is not
covered by the spec, note it in the PR; conflicts between owners are arbitrated
by the orchestrator, and by the human when outside the ADRs.

| Product decisions    | S3 (V1 SCR scope), S4 (auth), S5 (target server), S6 (Linphone target), public vs private publication |
| Owner conflict       | Final arbitration outside the ADRs                                                                    |

**Golden rule**: the agent moves fast on implementation, the human keeps ownership of the
**direction** (plans, ADRs, ports, product decisions). No merge happens without human
review on the areas listed above.
