# Roadmap

Plan par phases. **Règle** : une phase ne démarre que quand la précédente est
verte (tests + clippy + fmt). Chaque phase a un critère de sortie vérifiable.

| Phase | Contenu                                                                                                                                                                                                                                                                                       | Critère de sortie                                                 | Statut |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- | ------ |
| 0     | Setup : workspace, CI, licence, docs, AGENTS.md, specs embarquées (+ QA vs PDF officiels) : 6 specs CPM V2_2 + `OMA-TS-REST_NetAPI_NMS-V1_0-20190528-C` (base du binding REST, embarquée 2026-11-08), checklist SCR                                                                           | `cargo build/test/clippy/fmt` verts, repo commité                 | ☑ fait |
| 1     | `cpm-core` : modèles NMS/CPM + **ports** (`StoreBackend`, `MessageStorage`, `SyncStateStore` traits) + `SyncState` (blob sérialisable, D3) + mapping objectId↔id local. Golden tests depuis annexes B/C–H **extraites du PDF officiel** (pdftotext). `cargo-deny` (licences+advisories) en CI | tests golden avec les exemples JSON des annexes C–H de [CPM-REST] | ☑ fait |
| 2     | `cpm-nms` base : transport HTTP (reqwest/rustls), auth (Bearer/Basic), boxes, dossiers CRUD/list/search                                                                                                                                                                                       | tests `wiremock` sur `/nms/v1/base/{boxId}/folders...`            | ☐      |
| 3     | `cpm-nms` objets : CRUD + bulk + payloads multipart + flags                                                                                                                                                                                                                                   | tests `wiremock` + fixtures spec                                  | ☐      |
| 4     | `cpm-nms` sync : subscriptions, notifications, `restartToken`/`lastModSeq` ; `cpm-client` : first-time + steady-state, cache via traits                                                                                                                                                       | scénario 2 clients mockés convergent                              | ☐      |
| 5     | `cpm-msg` : parse/serialize CPIM (RFC 3862) + MIME multipart, mapping message CPM ↔ conversation Linphone                                                                                                                                                                                     | round-trip sur exemples spec                                      | ☐      |
| 6     | `cpm-ffi` : API C (cbindgen), build CMake dans linphone-sdk, exemple d'appel                                                                                                                                                                                                                  | linphone-sdk compile avec la lib liée                             | ☐      |
| 7     | Durcissement : fuzz du parsing (cargo-fuzz), perf, rapport de conformance SCR, **adapter IMAP** (`cpm-imap`, implémente `StoreBackend` sur Message_Store V2_2)                                                                                                                                | `docs/conformance.md` entièrement coché + `cpm-imap` compile      | ☐      |

Voir `docs/architecture.md` pour les décisions structurantes et
`docs/specs.md` pour les références normatives.
